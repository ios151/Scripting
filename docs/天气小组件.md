# 天气小组件

### ⬇️ [点此一键安装](https://www.scripting.fun/import_scripts/?urls=%5B%22https%3A%2F%2Fraw.githubusercontent.com%2Fios151%2FScripting%2Fmain%2Fdist%2FWeatherWidget.zip%22%5D)

**在 iPhone / iPad 上用 Safari 打开这个链接**，会直接唤起 Scripting 导入。
在电脑上点是没用的——那台机器上没有 Scripting。

主屏幕和锁屏的天气小组件：跟着你的当前定位，或者固定看一个城市。大号细体气温、逐小时一排（日落夹在整点之间）、多色天气图标，背景按天气和昼夜换天空色。中号和大号还带体感、湿度、风、空气质量，大号有明天起的几天（带温度条），有天气预警时卡片上会多一个徽章。

数据默认来自[彩云天气](https://www.caiyunapp.com/)，由 001 提供 API 接口，装好就有，什么都不用填。想用自己的彩云接口、或者备用的 [Open-Meteo](https://open-meteo.com/)（只有基础的天气），脚本页「天气来源」里可以换。中号、大号上画哪些数据也能在脚本页「显示样式」里换（风和湿度、未来几天、一句话 + 日落 + 空气……）。

> ⚠️ **真机验证还不完整。** 作者在真机上看过 1.1.0 的脚本页和中号小组件（能起、能显示、城市名能反查出来），也看过 1.3.0 的一种「显示样式」组合（中号：右上风和湿度、中间逐小时、底部一句话，字都放得下）；**1.2.0 新加的版面（中号底部一行、大号的未来几天）、预警徽章的新样式、彩云换成主数据源，和 1.3.0 的其余「显示样式」组合，还没在真机上验证。**
> 小组件里能不能联网、能不能现场定位，文档没写，也没有确证，脚本都做了退路。详见下面的「真机验证状态」。遇到问题开 issue。

## 要求

- Scripting：按 3.3.0（TestFlight 版）的类型定义开发，别的版本没试过。脚本用到的接口和组件，在 3.2.2 的官方文档里都能找到，没发现只有 3.3.0 才有的；旧版本也许能用，但没验证过
- 定位：第一次打开脚本时允许定位（小组件里弹不了授权框，授权要在脚本里给）；不想给也行，选一个固定城市
- 联网：要能访问你选的数据源（默认是内置的彩云接口）

## 它长什么样

背景是一张按天气和昼夜选的天空色（晴、多云、阴、雾、雨、雪、雷暴，各有白天和夜里），文字一律白色。图标是多色的：白云、黄太阳、蓝雨点。

| 尺寸 | 彩云（内置 / 自己的） | Open-Meteo（备用） |
|---|---|---|
| 小号 | 左上地名、右上天气图标，中间大号细体气温，下面天气和最高最低 | 一样 |
| 中号 | 左栏地名、气温、最高最低；右栏天气和降水概率、一条细线、逐小时一排 5 格；**底部一行：体感、湿度、风、空气质量** | 没有底部那一行 |
| 大号 | 地名；天气、最高最低和大号细体气温；逐小时一排 6 格；**明天起的 4 天（星期、图标、降水概率、最低、温度条、最高）**；**底部一行：体感、湿度、风、空气质量** | 老样子：逐小时两排共 10 格，没有后面的几天和详细数据 |
| 超大 | 没单独设计：横向的借中号、竖向的（iOS 27）借大号，按宽高放大 | 一样 |
| 锁屏圆形 | 图标和气温 | 一样 |
| 锁屏矩形 | 地名、气温和天气、最高最低 | 一样 |
| 锁屏单行 | 「阴 19° 17~19°」，前面带图标 | 一样 |

卡片底部**不写更新时间，也不写数据署名**。底部那一行平时是详细数据，有这几种情况会换成一句话：

- 「上次定位处的天气」：现在拿不到定位，用的是上次存下的位置
- 「刚才没刷新成功，显示的是之前的数据」：这次联网没成功，用的是缓存
- 「未来两小时有雨」这类说明：彩云判断未来两小时会下雨或下雪时才有，没有降水不写

没有位置、没有数据时各画一张说人话的卡片（「还没有位置」「天气暂时取不到」），点一下打开脚本。

详细数据里的项，缺了哪项就不画哪项，不拿默认值冒充。空气质量的标签和值之间有个按分级上色的小圆点（「空气 ● 优 47」，绿、黄、橙、红、紫、深红），带一圈白边，在任何天空色上都看得见；因为四项平分一行，卡片上写两个字的短名加指数（「优 50」「轻度 120」「重度 215」），脚本页「空气质量」里写接口给的全名（「轻度污染 120」）。

逐小时那一排：第一格是「现在」，后面是之后的整点，今天、明天里还没到的日出日落按时间夹在整点之间（日出日落那一格下面写「日落」，不写气温）。

**有天气预警时**，徽章占一个现成的位置，不另外加一行：

- 小号：换掉最高最低那一行
- 中号：换掉天气文字后面的降水概率
- 大号：放在地名那一行的右边
- 锁屏：矩形的第三行换成预警，单行换成预警短名，圆形里的天气图标换成三角

徽章是一个圆角小方块加一行字：方块的底色按级别（蓝、黄、橙、红，上浅下深的渐变加一圈细描边），里面的图案按预警类型挑（暴雨、大风、高温、雷电……，认不出的用通用的叹号），后面是白字「大风蓝色预警」，不止一条时带「+1」。背景的天空色不变。

## 怎么用

1. 打开「天气小组件」脚本，第一次会问你要不要允许定位，选允许。
2. 长按主屏幕空白处，点左上角的加号，找到 Scripting 添加一个小组件，长按它选「编辑小组件」，脚本选「天气小组件」。
3. 点一下小组件：打开这个脚本，里面有完整的天气、立即刷新和设置。

**看哪里的天气**（脚本页里的「位置」）：

- 跟着当前定位（默认）：显示你所在位置的天气
- 固定城市：不管你在哪，只看你选的那个城市。输入城市名，点「查找并使用」

**让某一个小组件固定看另一个城市**：在「编辑小组件」的「参数」里填 `纬度,经度,名称`，比如 `39.90,116.40,北京`（逗号中英文都行，名称可以不写）。参数优先于脚本页里的设置。

脚本页里的「预览小组件」可以不回主屏幕就看各个尺寸，包括锁屏的三种。

脚本页从上到下：

- 卡片预览、立即刷新
- 显示样式：中号、大号上画哪些数据（见下面「显示样式」）
- 概况：彩云的三句话——今天怎么样、未来 24 小时、未来两小时有没有降水
- 未来几天：每天一行（天气、最低到最高、降水概率），下面一行小字写风、湿度、空气、紫外线
- 详细数据：体感、湿度、风、云量、露点、气压、能见度、紫外线
- 空气质量：国标指数，和 PM2.5、PM10、臭氧、二氧化氮、二氧化硫、一氧化碳的浓度
- 生活指数：穿衣、舒适度、感冒、洗车
- 位置、天气来源、天气预警、现在的情况、小组件、数据来源

用备用来源时，概况、未来几天、详细数据、空气质量、生活指数这几节都不出现。读不到的项就不写，不拿默认值冒充。

## 显示样式

脚本页「显示样式」里可以换中号、大号上画哪些数据，改了马上生效（主屏幕的小组件会重画；脚本页上面的卡片预览就是中号，直接看得到）。
默认就是上面「它长什么样」写的样子。

| 选哪里 | 选项 | 画什么 |
|---|---|---|
| 中号：中间那一排 | 逐小时（默认） | 现在和之后的整点 |
| | 未来几天 | 明天起 5 天，每列：星期、图标、最高、最低 |
| 中号：右上那一行 | 天气和降水概率（默认） | 天气图标、天气、降水概率 |
| | 风和湿度 | 「北风 4级  湿度 94%」，整行在右栏里居中；天气图标挪到气温旁边，不写天气文字和降水概率 |
| 中号、大号：底部那一行 | 体感、湿度、风、空气（默认） | 四项平分一行 |
| | 一句话、日落、空气 | 一句话靠左、字大；日落（晚上写明早的日出）和空气靠右 |
| | 不显示 | 不画这一行（出了状况的提醒还是会写） |
| 一句话写什么（选了「一句话」才有） | 自动（默认） | 未来两小时有雨先说雨；否则明天比今天平均气温差 ≥ 3° 就写「明日平均降温 9°C」；再不然用彩云的一句话 |
| | 彩云的一句话 | 「今日多云，气温适宜」 |
| | 明天比今天冷还是暖 | 「明日平均降温 9°C」，变化不到 1° 写「明日气温和今天差不多」 |

- 选了「风和湿度」，底部那几项里就不再重复写风和湿度（只剩体感、空气）；有预警时右上那一行让给徽章（徽章靠左，不跟着居中），风和湿度改写在底部。
- 「明日平均降温」用每天最高最低的中间值算，不是真的日平均气温。
- 选了「未来几天」或「一句话」，中号竖向放不下原来的字号，会换成紧凑一点的（气温 40 而不是 44，逐小时的字也小一号）。
- 大号只有底部那一行能换；小号、锁屏不变。
- 备用来源（Open-Meteo）没有这些数据，选了也按默认的样子画；没有明天的数据、读不到风和湿度时，对应的那一处也退回默认。
- 选「彩云的一句话」「明天比今天冷还是暖」时，未来两小时有雨也不会单独提示（只有「自动」会先说雨）。
- 选过别的之后，「恢复默认样式」才会出现。
- 你的选择存在这台手机的脚本存储里，清空缓存不动它。

## 天气来源

脚本页「天气来源」里选，三种：

| 来源 | 有什么 |
|---|---|
| 内置（默认） | 彩云天气，由 001 提供 API 接口。装好就有，什么都不用填。天气、详细数据、未来几天、预警一次请求到齐 |
| 自己的彩云接口 | 同上，只是换成你自己的服务地址和 token |
| Open-Meteo（备用） | 只有基础的天气：当前气温和天气、逐小时、今天明天的最高最低和日出日落。没有详细数据、未来几天、预警 |

换了来源，旧的缓存立刻作废，下一次刷新按新来源取；选「内置」或「Open-Meteo」时，自己填过的地址和 token 也留着，下次切回来不用重填，要删就点「清除自己的设置」。

### 自己的彩云接口

选「自己的彩云接口」，填服务地址和 token，点「保存并测试」，会立刻查一次并告诉你结果（接口可用 / 当前位置现在有几条预警 / 哪里不对）。

- 地址要以 `https://` 开头（token 在路径里，不能明文发），可以带端口和路径前缀；多写的结尾斜杠和 `/v2.6` 会自动去掉
- token 是路径里的一段，任意文字都行，只是不能是空的、不能带斜杠，最长 128 个字
- 用彩云官方的服务：地址填 `https://api.caiyunapp.com`，token 填你在彩云平台申请的
- 自己搭转发服务也行，只要路径和彩云官方一样：`{地址}/v2.6/{token}/{经度},{纬度}/weather?alert=true&dailysteps=6&hourlysteps=24&lang=zh_CN`

自己填的地址和 token 只存在这台手机的脚本存储里，不写进脚本文件，也不会导出。

**额度和条款**：内置接口的额度由 001 管；用自己的 token 时以你自己的彩云后台为准（彩云文档页没写调用额度和使用条款）。天气最多每 15 分钟联网一次，一个小组件一天最多约一百次，几个小组件看同一个地方时共用缓存。

### Open-Meteo（备用）

[Open-Meteo](https://open-meteo.com/) 的公开预报接口（`api.open-meteo.com/v1/forecast`），不要密钥：

- `current`：气温、天气代码、是否白天
- `hourly`：气温、天气代码、降水概率、是否白天
- `daily`：最高最低、日出日落
- `timezone=auto`、`forecast_days=2`

**免费接口的限制**（2026-11-02 查的官网[条款页](https://open-meteo.com/en/terms)和[价格页](https://open-meteo.com/en/pricing)，以官网当前的为准）：

- 只能非商用：个人用、非营利、没有订阅也没有广告，可以；放了订阅或广告就算商用，要买它的订阅
- 次数：每分钟 600 次、每小时 5000 次、每天 10000 次、每月 30 万次
- 限额按 IP 地址和应用算；滥用的会被封，不另行通知。用 Vercel、Netlify 这类服务转发容易更早被限（它建议用 Cloudflare Workers）
- 没有可用性保证，数据也不保证准确
- 一次请求算一次调用；变量超过 10 个、或者超过两周的数据会按比例多算一点（这里是 11 个变量、2 天）
- 这里的用量：天气最多每 15 分钟联网一次（只有点「立即刷新」才会越过缓存），一个小组件一天最多约一百次，几个小组件看同一个地方时共用缓存，还要更少；离每天 10000 次差得远

**署名**：Open-Meteo 的数据按 CC BY 4.0 提供，要署名。卡片上不画，署名写在脚本页「数据来源」里：「Weather data by Open-Meteo.com」，带链接和许可，见 [NOTICE.md](../NOTICE.md)。只有选了备用来源，才会用到它的数据。

### 发出去什么

取整到小数点后两位（约 1 公里）的经纬度，加上联网都会带的 IP 地址，不含账号和设备名称。选「内置」时发给 001 的接口，选「自己的」时发给你填的地址，选「Open-Meteo」时发给 Open-Meteo。城市名用系统的地图服务反查，不经过上面任何一家。

### 署名和出处

- 天气和预警数据来自彩云天气，由 001 提供 API 接口
- 彩云相关文档来自小麦（Telegram @GetSomeTriticum）
- 这两句和 Open-Meteo 的署名都在脚本页「数据来源」里；卡片上不写

## 详细数据怎么来的

彩云的综合接口 `/weather?alert=true&dailysteps=6&hourlysteps=24&lang=zh_CN` 一次请求带回实况、逐小时、每天、空气质量、生活指数、未来两小时降水的说明和预警（一次请求就是一次调用）。拿内置接口实测过一份真实返回，有几处和[彩云文档](https://colorfulclouds.apifox.cn/)对不上，脚本都兜住了：

- **昼夜**：晚上九点也会返回「晴（白天）」，所以昼夜按经纬度自己算（NOAA 太阳位置算法，误差一两分钟），不看返回里的 DAY / NIGHT
- **日出日落**：每天的数据里没有（文档说有 `astro`），同样自己算
- **今天的最高最低**：只算「剩下的时间」（晚上九点的返回里，今天最高最低是 14° / 13°，白天的最高早就不在里面了），所以把今天已经取到过的最高最低累计起来，并且至少包含现在的气温；位置挪出 5 公里之外就不累计
- **逐小时的时间**不在整点（21:22、22:22……）：按小时归整，和 Open-Meteo 的整点对齐
- **占位的 0**：已经过去的时段在白天 / 夜晚那几组数据里写成 0，只用全天的那一组
- **读不出来的单项**就当没有，不拿默认值冒充；只有「没法定位当前天气」才整份当作读不懂

单位：湿度和云量是 0~1 的小数、气压是 Pa、风速是 km/h、能见度是 km、污染物是 μg/m³（一氧化碳是 mg/m³）；换成界面上的百分数、hPa、风力等级（国内天气预报说的「几级风」）、km。风向按「风从哪边来」叫（东南风是从东南吹来）。

用到的字段（对着文档里 realtime、minutely、hourly、daily 四份说明）：

- 实况：温度、体感、湿度、云量、露点、风、气压、能见度、天气现象、空气质量（国标指数和文字、六项污染物）、生活指数里的紫外线
- 每天：最高最低、天气现象、降水概率、平均风、平均湿度、平均空气质量、紫外线、生活指数（穿衣、洗车、舒适度、感冒）
- 逐小时：天气现象、气温、降水概率；`hourly.description` 那句「未来 24 小时……」
- 分钟级：`minutely.description` 那句「未来 2 小时……」，和未来两小时每分钟的降水强度（用来判断卡片底部要不要写那句话）
- 没用的：阵风 `gust`（样例里是 1.42，和风速 5.11 km/h 换成 m/s 一模一样，看着单位不是 km/h，拿不准就没用）、`dswrf`、最近降水带 `precipitation.nearest`、逐小时的风 / 湿度 / 空气（卡片放不下）

## 天气预警

预警和天气是同一次请求带回来的（`alert=true`），所以**没有单独的联网、缓存和提示**：取到了就跟着天气一起存，没取成功就和天气一起退回缓存。用备用来源（Open-Meteo）就没有预警。

**什么时候显示、什么时候不显示**：宁可少显示，也不显示过期的，更不把「没取到」说成「没有预警」。

- 缓存还新、位置也没挪出 5 公里：直接用，不联网
- 联网失败：缓存里的预警不超过 3 小时就继续用，超过就不显示
- 现在没有预警：卡片上什么都不画（不写「无预警」）
- 接口的返回里没有 `alert` 字段：脚本页写「接口没有返回预警数据」，徽章不显示；不当成「没有预警」，下次照常再查
- 有 `alert` 字段但读不懂：脚本页写「返回的内容读不懂」，徽章不显示
- 已经解除、取消的预警不显示；同一条预警出现两次只留一条
- 同时有几条时，亮级别最高的一条（红 > 橙 > 黄 > 蓝），同级的亮发布得晚的；读不出级别的按黄色画、按黄色排，不会被蓝色的盖住

**名字和级别怎么读**：文档没给预警代码表，只有一个例子（`0501` 对应「大风蓝色预警」）。名字优先从标题里取（「海淀区气象台发布大风蓝色预警」→「大风蓝色预警」），取不出来再用代码，再不行就用标题原文截短；级别优先看代码后两位（01 蓝、02 黄、03 橙、04 红），没有代码就看标题里的「X色预警」。代码表是按国内预警信号的通行编码补的，不是彩云文档里的。图案按预警类型挑（先看名字里的关键词，再看代码前两位），认不出的用通用的叹号。

**预览预警样式**：真的预警难得遇上，所以脚本页「天气预警」里有个「预览预警样式（10 分钟）」：不管选了哪种来源、不联网，主屏幕和锁屏的小组件上会出现两条写着「示例」的假预警，10 分钟后自己消失，也可以点「结束预览」立刻收掉。到点之后：脚本页开着的话，会自己收掉并让主屏幕的小组件重画；脚本页没开的话，已经画好的小组件要等系统下一次重画才会换回来，最长约 20 分钟。用它就能在真机上看各个尺寸里徽章长什么样、长名字怎么缩。要先有天气显示（有位置）才看得到。

**预警仅供参考，以官方发布为准。没看到预警，不等于没有预警**：联网出问题、接口没返回预警数据时也不会显示。

## 位置和刷新

**位置按这个顺序取**：小组件参数 → 固定城市 → 现场定位 → 上次存下的定位 → 都没有（画「还没有位置」）。

**刷新规则**：

- 数据不到 15 分钟、位置也没挪出 5 公里，就直接用缓存，不联网
- 位置挪出 5 公里，天气和城市名都重查；不到 5 公里城市名不重查
- 挪远后反查不到新城市名，先显示「当前位置」，不让旧城市名配着新位置的天气
- 联网失败：整个保持原样，旧缓存和旧城市名一起留着，底部提醒；没有缓存就画「天气暂时取不到」，脚本页「天气来源」的状态里写原因（token 无效、请求太频繁、联网失败、接口出错、返回的内容读不懂）
- 请系统 20 分钟后再画一次，没取成功就 10 分钟（系统只当它是提示，按预算给，不准点）
- 小组件里各步最多等多久：定位 3 秒，联网 6 秒（外面再兜 2 秒），反查城市名 3 秒（和联网同时进行）。小组件一旦卡住就是一片空白，所以每一步都有上限

版面和这套刷新规则，移植自作者自己的虚拟定位 App（RoamControl）里的天气功能（那部分是作者自己写的，见 [NOTICE.md](../NOTICE.md)）；数据拼装那一段拿它的 Python 移植对拍过 281 个变体。

## 已知局限

- **内置接口目前没有返回预警数据**（2026-11-02 实测，接口修好后这条就不成立了）：拿中国天气网当时有预警的 9 个地方试过，天气数据都正常，但返回里一个 `alert` 都没有。所以脚本页的预警状态现在会写「接口没有返回预警数据」，徽章不会出现；接口修好之后不用更新脚本，下一次刷新就会用上。
- **有预警时真实返回读不读得懂，还没验证过**：自测用的是照彩云文档字段手搭的样例，不是真实返回。读不懂时脚本页会写「返回的内容读不懂」，徽章不显示。
- 预警代码表是按通行编码补的，不是彩云文档里的；名字和级别优先看标题，所以多数情况不受它影响。
- 预警取不到（没网、token 失效、额度用完）时不会在卡片上提示，只在脚本页「天气预警」里写原因：小组件上多一条「预警失败」的提示，比偶尔少一个徽章更吵。
- 「现在」那一格是取数那一刻的，缓存最长用 15 分钟，再加上系统重画的延迟；不是实时（卡片上不写更新时间，脚本页「现在的情况」里有）。
- 用彩云时，今天的最高最低是「取到过的最高最低累计起来」的：当天第一次取数晚了（比如晚上才第一次打开），白天已经过去的最高会比实际低；位置挪出 5 公里之外就从头累计。
- 用 Open-Meteo 时，国内是全球模式（9~25 公里分辨率），没有分钟级降水；`current` 是模式值，不是实测。
- 用备用来源时没有详细数据、未来几天、预警，卡片上也不留空位。
- 大号里「明天起的几天」最多画 4 天（接口给 5 天，竖向放不下更多）；脚本页「未来几天」不受限，有几天写几天（今天起 6 天）。
- 卡片底部那一行（中号、大号）四项平分一行，所以空气质量写两个字的短名加指数；逐项的字有没有被截断只能上真机看。
- 「显示样式」里每一种组合的竖向都算过，但真实的行高只能上真机看；最挤的是中号的「未来几天 + 一句话」，只比留的安全余量多一点点。
- 「明日平均降温 / 升温」比的是明天和今天每天最高最低的中间值；今天的最高最低是累计出来的，当天第一次取数晚了，今天的平均会偏低，「升温」会偏大、「降温」会偏小。
- Open-Meteo 的 CC BY 署名只在脚本页里，卡片上没有。
- 染色（Tinted）主屏幕模式下背景会被系统隐藏、图标被统一染色，没单独设计。
- 超大尺寸没单独设计，只是借中号 / 大号放大。
- 模拟定位时天气跟不跟着走，取决于系统定位给小组件的是不是模拟位置：这个脚本只读系统定位。
