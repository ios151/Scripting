# JavBus

### ⬇️ [点此一键安装](https://www.scripting.fun/import_scripts/?urls=%5B%22https%3A%2F%2Fraw.githubusercontent.com%2Fios151%2FScripting%2Fmain%2Fdist%2FJavBus.zip%22%5D)

> 非官方客户端，不提供任何内容，所有数据来自第三方站点。**含成人内容，未满十八岁禁止使用。**

把 Nicked639 的 JSBox 脚本 **JavBus 9.2**（「你口袋中的 AV 辞典」）移植到 Scripting。
原脚本的功能清单、请求的页面、解析方式都是逐条对着源码核出来的，UI 用 Scripting 的原生组件重写。

> 原脚本是 **JSBox** 脚本（`$ui` / `$http` / `$cache` / `$file` / `$quicklook` / `$objc` / web 视图…），
> 不是 Quantumult X / Loon / Surge 脚本，也不是油猴或 Node 脚本。

## 要求

- Scripting：按 3.3.0（TestFlight 版）的类型定义开发，App Store 版（3.2.x）没试过
- 能访问 `www.javbus.com`（部分网络要代理；站点的年龄验证见下面「站点年龄验证」）
- 网友推荐的提交 / 撤销 / 举报走社区推荐服务（`javbus-community.javbuss.workers.dev`），`workers.dev` 在部分网络下也要代理

### 做不了或改了形态的部分

不是漏做，每一条都有原因：

- **Today 小组件**（原版 `$app.env == $env.today`）：iOS 14 起 Today 视图被 WidgetKit 取代，小组件读不了剪贴板、
  放不下完整界面。替代：`scripting://run/JavBus?code=番号`、分享表单（`intent.tsx`）、启动时读剪贴板——
  原版小组件做的事（看剪贴板里有没有番号、直接搜）这三条都覆盖了。原版小组件里的「应用打开」按钮因此没有意义，没做。
- **脚本自更新**（`$addin.save` 下载新版覆盖自己）：JSBox 专有；而且原版查更新的 `updateInfo` 和「更新说明」读的
  `Readme.txt` 在 GitHub 上现在都是 404。替代：用 Scripting 自己的导入 / 远程资源更新；「更新说明」读不到远程时显示内置版本。
- **Avgle 联动**（`jsbox://run?name=Avgle` 调起另一个 JSBox 脚本）：别的脚本调不了，而且站点已经停止服务
  （2026-10 实测 `api.avgle.com` 返回 520）。原版 9.2 把 Avgle 从「获取」菜单里去掉了（9.1 里还有，这里的第一版也有一个直接查接口的替代，现已删除），
  所以现在同样没有。原版里的「Avgle 预览」菜单项本来就永远不会出现（`Avgle` 标志只在它自己的处理函数里才会置位），也没做。
- **「分享 JSBox 链接」**：原版分享 `https://shadowNicked.github.io/?code=XXX`（一个会跳到 `jsbox://` 的中转页）再过 is.gd 缩短，
  那个中转页只认 JSBox。Scripting 没有 https 入口，默认分享 `scripting://run/JavBus?code=XXX`；
  设置里可以填自己的中转页模板，http(s) 开头的会照原版过一遍 is.gd。
- **点磁链推送到 Quicker**：原版第一次点磁链时现场弹输入框要邮箱和口令。改成在「设置 → Quicker 推送」里配置，
  没配置就只复制，不在点磁链的当口逼人填表。
- **手势变化**：原版首页下拉弹「作者声明 / 更新说明」、推荐页下拉打开 JavLibrary 高分榜、预览按钮长按直接播 Jable 预览。
  现在下拉统一是刷新，声明和更新说明在右上角「更多」里，高分榜是推荐页导航栏上的按钮，
  Jable 预览在「预览」菜单里。
- **取消收藏 / 归档 / 删除后不再自动退出详情页**：原版是 `$ui.pop()`。Scripting 里在 `NavigationLink` /
  `navigationDestination` 推进来的页面上调 `Navigation.useDismiss()`，关掉的是整个脚本而不是返回一步
  （官方文档 navigation_stack 一节明说，要返回一步得改 `path`），所以只更新状态：主按钮随之变成「收藏」
  「已归档」「已删除」，返回列表时列表已经是新的。演员页、类目页里的「取消收藏」同理。
- **详情页换了版式（媒体中心风格，照 One-ipa 的详情页）**：原版底部固定三个灰色方块（获取 / 预览 / 收藏），和整页的样子对不上，
  现在改成：背景是糊掉的封面；顶部固定一个舞台（点播放前是封面海报、之后换成播放器，固定在滚动区外面，往下读片名信息时画面还在；播放中被磁链 / 演员 / 类目这些子页面盖住会暂停，退回来接着播）；
  下面依次是标题与评分、白色大「播放」胶囊 + 收藏胶囊、两行小胶囊（获取 / 预览 / 磁链 / 样品图；分享 / 推荐）、片名信息卡片、参演的横向头像卡片。
  大「播放」按挑片源：完整视频（MissAV > Jable）> 预览（MissAV > Jable），探测还没完就提示稍等，都没有就试 Fanza 预告，第二行字写明会播哪个。
  手势的变化：封面点按原版是看大图，现在是播放，长按菜单里有「查看大图 / 分享封面链接」；「磁链」「样品图像」原来藏在两个菜单里，现在是单独的胶囊。
- **整个脚本是深色外观**（照详情页的风格），不跟随系统浅色：五个 Tab 页和所有子页面共用 `pages/theme.tsx` 的令牌和部件。
  背景是深色渐变 + 顶端一抹带颜色的光（最新红、女优粉、分类蓝、推荐橙、收藏玫红），演员页和详情页用封面 / 头像糊背景；
  系统的分段控件换成自绘的半透明白胶囊分段（选中的一段白底黑字，和详情页的白色大「播放」同一个语气）；搜索栏、筛选条、徽章也都是胶囊；
  影片卡片封面压一层底部渐变，渐变上是番号（粗）和日期（淡），已收藏在右下角点一颗红心，已归档压暗虚化再点一个归档盒
  （原版是整张染渐变色 / 盖白膜，深色底上不好看）；演员页的资料放进半透明卡片，收藏用胶囊。
  设置和磁链仍然是系统 `List`（磁链的左滑分享、设置里的 Toggle 都靠它），只用 `scrollContentBackground("hidden")` 把底透出来，行的颜色交给深色模式。
- **详情页主按钮是逐步切换的**（和原版一样，`core/phase.ts`）：收藏 → 取消收藏 → 收藏…；归档 → 已归档；删除 → 已删除，
  点完立刻变，不按库状态重算。唯一的改动在推荐页：原版从推荐页进入时，已收藏的片给「归档」，点「收藏」之后又变成
  「取消收藏」，同一部片两种说法；这里推荐页和浏览入口一致，已收藏就是「取消收藏」（想归档去收藏 Tab 里进）。

### 我的精选

用法：**收藏 = 待看清单**（看了预览感兴趣的、别人推荐的高分片），**看完点归档**，**再按自己的喜好给它打星**，打了星的就是「我的精选」。

- **在哪打星**：已归档的影片，详情页第二行小胶囊里有「精选」（空心星 = 没标，金色实心星 = 已标，再点取消）；归档页里长按影片也有「加入 / 移出我的精选」。
  没归档的片没有这个按钮——精选只对归档里的片有意义。
- **在哪看**：归档页顶上多了一排「全部 N | 我的精选 M」，切到「我的精选」只看打了星的，最近打星的排最前，和上面的番号过滤可以一起用；归档里的卡片右下角打了星的有一颗金色小星。
- **顺便推荐给网友**：在详情页点「精选」打星时，如果这部片还不在推荐列表里，会弹一个选单：「只加入我的精选」或「加入并推荐给网友」（后者等于同时点了「推荐影片」，
  **会公开提交**到「网友推荐」，选单里写着）。已经在推荐列表里的就不问了。取消精选**不会**撤销已经提交的推荐，撤销还是在「推荐影片」菜单里；归档页长按菜单里的打星是纯打星，不弹推荐。
- **数据**：存在收藏库里的 `picks`（`core/library.ts`，影片 shortCode 的数组，最近打星的在最前），恒是归档的子集：删除归档的同时精选也没了（再归档回来不会自己带着星），导入时洗掉不在归档里的。
  **只在本机**，服务端不知道你的精选；换设备靠备份文件（导出的 JSON 多一个 `picks` 字段——原版没有这个字段，原版导入时是否忽略它没有验证过；合并导入是本机的在前、备份里新的追加，覆盖导入就是备份里的）。设置页的数量里也有一行「我的精选」。
- **没有的**：精选不会自动变成推荐，除了归档页的筛选也没有别的用法（比如排序）；推荐页里「我推荐过的」依然没有单独的列表（服务端只按设备编号认「这条是不是你提交的」，只用来让你撤销）。

### 和原版行为不一样的地方（修了原版的毛病）

| 位置 | 原版 | 这里 |
|---|---|---|
| 详情页参演头像 | 头像地址是绝对路径时，把整段 `<a>` HTML 当成图片地址（图裂） | 按地址解析 |
| 详情页缺字段 | 缺封面或識別碼整页 `exec(...)[n]` 抛 TypeError | 缺字段给空值 / 「未知」 |
| 磁链解析 | 名字取 `dn=` 参数（没有就抛错），大小日期按 `href…</a>` 出现顺序取（标签带 href 就错位） | 按单元格取，名字优先用链接文字 |
| 高清 / 字幕角标 | 整块 HTML 里搜这两个字，片名 / 磁链名带「字幕」就误标 | 认站点给标签按钮加的 `title="包含…的磁力連結"`（列表和磁链行都是） |
| 页面被拦 | 不看 HTTP 状态码，Cloudflare 挑战页 / 5xx 当成「没有结果」，搜索逐站跳过后报「搜索无果」 | 403 / 429 / 5xx 抛错并提示「站点返回 N」 |
| 旧备份里的演员头像 | 原版把整段 `<a>` HTML 存成了头像地址 | 导入时能抠出 `<img src>` 就用，抠不出置空显示占位图 |
| 推送到 Quicker | `encodeURI(磁链)`，磁链里的 `&dn=` 被当成另一个参数，电脑上收到的是截断的磁链 | `encodeURIComponent` |
| 标题翻译 | 靠「丢掉响应的最后一项」去掉音译 | 只拼带 `trans` 的分句 |
| 分类小节 | 写死标题表（有码 7 节） | 按页面实际 `<h4>` 解析，站点新增的小节（如有码页的「其他」）自动出现 |
| 渐变色块 | 每次渲染随机取色，列表一刷新颜色就跳 | 按文字哈希稳定取色 |
| 图片相对路径 | 演员列表和演员作品里直接拼在当前 `homepage` 后面，恰好在无码首页时多一层 `uncensored/`（首页列表有 replace 补丁，这两处没有） | 一律按页面所在域名解析 |
| MissAV 完整视频 | `src` / `currentSrc` 可能是 `blob:`，照样当片源缓存 | 只认 http(s)，轮询落空再从页面源码找 m3u8 |
| 样品图下载文件名 | 按完成先后编号，并发下两次编号不一样 | 按图片序号编 |
| 取消收藏 / 归档 | 只按 shortCode 删，旧数据里番号对不上就删不掉 | shortCode 和番号两个都认 |
| JavDB 评分 | 取搜索页里**第一个**评分块，不看是哪部：要找的番号没收录时，显示成别的片的评分；请求失败、没评分都是同一个 N/A | 按卡片切开、按番号（忽略大小写和连字符）精确匹配，对不上就是 N/A；「获取失败」单独写出原因；被拦时用浏览器内核再试一次；评分单独占一行，长按可重新获取 |
| 推荐上传出错 | 服务端回的是 Google 错误页时，把整页 HTML 当「错误代码」塞进提示，真机上是满屏脚本 | 只取页面上看得到的几句话，弹窗展示并复制；整页 HTML 不进提示、不进剪贴板 |
| 推荐上传的跳转 | `$http.request` 发 POST，Apps Script 回 302 后怎么处理全靠 JSBox 的默认行为（能拿到结果码，说明默认是改 GET 去取） | 显式 `handleRedirect` 改成 GET 并去掉请求体和 `Content-Type`，不赌 Scripting 的默认怎么处理 302 |
| 网友推荐的上传 | 只有原作者一个人能维护；服务端的 GitLab 令牌失效后，上传一律失败，也没人能修 | 网友推荐改走社区推荐服务（见下）：大家一起维护，有审核 / 举报 / 自动检查；作者精选还是原作者的 |

### 对标原版 9.2

  客户端会不会真的用 304（取决于 Scripting 的 `fetch` 有没有 URL 缓存）没验证过，不影响正确性。

### 片源和片源诊断

进详情页会同时去找四样东西，找到的按「完整视频 > 预览」排，「播放」按钮的第二行写的就是现在会放哪个：

| 片源 | 怎么找 | 备注 |
|---|---|---|
| MissAV 预览 | 请求 `fourhoi.com/<小写番号>/preview.mp4` 的前两个字节 | 图床不在 Cloudflare 验证后面。2026-10-23 抽样 38 个推荐里的番号，37 个有 |
| Jable 搜索 | `jable.tv/search/<番号>/` → 解析搜索结果 → **挑番号对得上的那一条** | 先用普通请求，被 Cloudflare 验证页挡住（403 / 标题「Just a moment...」）才改用**浏览器内核**（`WebScraper`，能跑验证页里的 JS）。以前只有普通请求，一被挡就等于「没有这部片」。结果里只认番号对得上的那一条（FC2 的 `FC2-PPV-123` 和 `FC2-123` 算同一个） |
| Jable 完整视频 | 搜索命中后取播放页，抠里面的 `var hlsUrl = '…m3u8'` | 同样「先普通请求、被拦再浏览器内核」。地址带 `expires` 令牌（Wayback 里的一份大约两小时有效），所以每次进详情页现取、不缓存 |
| MissAV 完整视频 | 隐藏的网页视图加载 `missav.ws/<小写番号>`，轮询视频地址，最长 80 秒 | 页面地址以前用的是原样的大写番号，现在和预览一致用小写（站点认不认大写没法验证） |

**为什么要加诊断**：用户反馈「大部分视频都没有完整版」。fourhoi 上的预览几乎都有，说明 MissAV 的片多半是有的；而在开发机上（经你的代理）`missav.ws` 和 `jable.tv` 的页面
8 种 UA / 大小写组合全部返回 403 的「Just a moment...」验证页。光看「有 / 没有」分不清是这部片真没有、被验证页拦了、超时了还是页面改版了，所以每一步都记下来。
手机上是不是同样被拦、浏览器内核能不能过验证、要多久，没有在真机上验证过——这正是诊断要回答的。

**怎么看**：详情页第二行小胶囊里的「片源诊断」（听诊器图标）。弹窗里每个片源一段：结果（取到了 / 没有 / 失败 / 进行中）、用时、最后一步、原因，下面有「复制」可以整段发给开发者。例如：

- `原因：直接请求：HTTP 403；浏览器内核拿到的还是 Cloudflare 验证页`：两种取法都被拦了，多半是你现在的网络出口被站点判成可疑，换个节点、关掉代理试试；
- `页面标题「Just a moment...」：这是 Cloudflare 验证页，网页视图没能通过验证`：MissAV 那条的同类情况；
- `搜到 N 条，但没有番号对得上的（第一条是 xxx）`：Jable 搜到了别的片，我们不再像以前那样直接拿第一条（那样放出来可能是另一部片）；
- `HTTP 404（站点上没有这个页面）` / `搜索结果是空的`：这部片 Jable 真没有，算「没有」，不是失败。

两条完整视频的路都试过、都没取到，手上只有预览时，「播放」按钮第二行会多一句「· 无完整视频」，提醒去看诊断（设置里关了「后台预取 MissAV」、又没手动点过 MissAV 完整视频时，MissAV 那条路没试过，不会写这句）。
Jable 搜索要是走到了浏览器内核，最长要 40 秒才能下结论（10 秒直接请求 + 30 秒浏览器内核），这段时间「播放」按钮仍然可以放已经找到的预览。

**浏览器内核不能无节制地开**（`kit/sourceProbe.ts` 的 `createScraper`）：隐藏网页视图吃内存、被拦的时候又每次都白等 30 秒，所以——

- 一次只跑一个，同时进几个详情页会排队；
- 轮到它时你已经离开了那个详情页，就不加载了（诊断里写「你已经离开详情页」，算「没有」不算失败）；
- 浏览器内核失败（超时 / 还是验证页 / 报错）后 2 分钟内不再试，直接写「N 秒前浏览器内核刚失败过，2 分钟内不再重试」；过了 2 分钟再进详情页会重试，换了节点也就能重新试；
- 自己计时：到 30 秒不管 `WebScraper` 有没有回话，都取消它并交出「超时」。
首页搜索框里「有没有预览」的判断还是原来的普通请求（`kit/previews.ts`），没有用浏览器内核，免得搜索变慢。

### 外部播放器

播放器右下角的 ↗ 菜单：Infuse / SenPlayer / VLC / nPlayer 已经内置，直接选；另外还有「自定义播放器」「复制视频链接」「分享链接」。
原版只有 nPlayer（9.1 / 9.2 一样），其余是照 One-ipa 的写法加的。内置的四个，拼出来的链接是：

| 播放器 | 链接模板 |
|---|---|
| Infuse | `infuse://x-callback-url/play?url={url}` |
| SenPlayer | `senplayer://x-callback-url/play?url={url}`（载入了字幕时多一个 `&sub={字幕地址}`，见下面「带字幕」） |
| VLC | `vlc-x-callback://x-callback-url/stream?url={url}` |
| nPlayer | `nplayer-{raw}` |

「自定义播放器」用设置里「外部播放器 → 自定义链接模板」；没填过的话，点它会就地弹出同一个输入框，填好直接用，也存进设置。
说明和例子在这个输入框里，设置页上只留了一行字。

**模板里必须有 `{url}` 或 `{raw}`**，打开时换成这条视频的地址（出现几次换几次，两种可以混用）：
`{url}` 是百分号编码后的地址（`:` `/` `?` `&` 都编码），放在 `?url=` 这类查询参数里用；
`{raw}` 是原样的地址，放在 `nplayer-{raw}` 这种「前缀 + 地址」的写法里用。

例：视频地址是 `http://192.168.31.8/video/test.mov`，模板 `senplayer://x-callback-url/play?url={url}` 实际打开的是
`senplayer://x-callback-url/play?url=http%3A%2F%2F192.168.31.8%2Fvideo%2Ftest.mov`。
把示例里的地址原样抄进模板不行：没有占位符，每部片都会打开同一个视频，脚本会拒绝并提示。
（scheme 大小写不影响；SenPlayer 已经内置，不用自己填，这里只是借它讲写法。）

两点限制：外部播放器只拿到一个地址，带不了请求头——MissAV / Jable 的 HLS 常常要 Referer，内置播放器会补，外部的未必能播
（遇到这类地址，菜单顶上会多一行灰色提示）；没装对应的 App 时，提示「打不开 …」。

**带字幕**：在内嵌播放器里载入了字幕（见下面「字幕」）以后，↗ 菜单里的「SenPlayer 打开」会变成「SenPlayer 打开（带字幕）」，
把字幕地址作为 `&sub=` 交给 SenPlayer——字幕由它自己渲染，全屏、画中画里都有（内嵌播放器的字幕画在小窗和我们自己的「全屏」里，画中画里没有）。
`sub` 的写法来自 SenPlayer 的 URL Scheme 文档（App Store 的更新说明里也写着 URL Scheme 播放支持外挂字幕），字幕地址和视频地址一样整体编码。
别的播放器暂时不带字幕（Infuse 的官方文档里也有 `sub`，没接）。

**Referer**：目前两个都设不了。
- SenPlayer：开发者说现在 URL Scheme 不支持 Referer、以后会加（用户转述）。等发版后看新文档里的参数名，接法和 `sub` 一样，是启动地址里多一个参数。
  文档页（腾讯文档）是 JS 渲染的，抓不到正文，所以参数名我没法提前猜；公开资料里能见到的只有 `url` / `name` / `ua` / `sub` / `saveURL` / 起播时间。
- Infuse：官方 API 文档（support.firecore.com 的「API for Third-Party Apps」）里 `play` 只有 `url` / `position` / `filename` / `sub` / `x-success` / `x-error`，
  没有请求头参数；社区里有人提了「支持自定义 HTTP 请求头」的建议帖，没有官方回复。另外社区有人反馈 Infuse 8.5.7 起通过 x-callback-url 打开 HLS（`.m3u8`）直接报错
  （2026-10-16 的帖子，官方还没回复）——MissAV / Jable 的完整视频都是 HLS，Infuse 眼下未必能播。

所以要 Referer 的地址（MissAV / Jable 的完整视频）交给外部播放器未必能播：先用内置播放器，
或者在自己的代理工具（Loon / Surge）里给那个 CDN 域名加一条「请求头加 Referer」的规则。

### 全屏（横屏）

播放完整视频时，播放器控制条里有「全屏」按钮（小窗里在底部那排圆钮的最右边）：点它，界面转成横屏，整页让给播放器——播放器铺满、下面的内容不画、
导航栏收起；全屏里按钮的摆法见下面「播放器控制条」。字幕叠层照常在（字号按叠层的实际大小算，横屏约 25）。
退出（或者离开页面）会转回竖屏。按代码，转横屏时同一个播放器节点一直挂着、只是大小变了，视频不该重新载入（没在真机上验证）。

怎么转的：`Device.supportedInterfaceOrientations = ["landscape"]`（`kit/orientation.ts`，类型定义写明只有 iPhone 有效）。
**2026-10-22 真机实测**（当时临时加的诊断按钮弹出的读数，已拆掉）：这样能转——手机竖着拿，设备方向还是 portrait、`isLandscape = false`，
屏幕尺寸照样从 440 × 956 变成 956 × 440，读回来的允许方向是 `["landscape","landscapeLeft","landscapeRight"]`；你在 Scripting 里配的方向是 `["portrait"]`。
退出时先只许 `["portrait"]` 把界面转回来，等 0.8 秒再还原成你配的方向（光把允许的方向放宽不够：横着的界面仍然被允许，不会自己转回去；
退出这一步真机上转回竖屏是看到过的——第一版的兜底还原就是这么把界面转回来的——但「先只许竖屏再还原」这套完整流程没有在真机上验证过）。

**界面转过去没有，怎么知道**：点「全屏」的同时页面就换成全屏布局（`MovieDetailPage` 里一个 `fullscreen` 状态，布局不给死尺寸、有多大占多大），
再每 100 毫秒读一次 `Device.screen`（`waitForLandscape`）确认：它是活的，旋转完读到的就是新的大小（诊断时在定时器里读到了 956 × 440）；
2.5 秒还没转过去才提示「这台设备转不了横屏」并退回平时的布局。退出是反过来：先转回竖屏，读到竖了才换回平时的布局，免得在横着的时候闪一下排错了的竖屏页。
**第一版栽在这儿**：用 `GeometryReader` 量页面大小，宽 > 高才切全屏布局，兜底 1.5 秒没等到横着的大小就判成「转不了」并还原。
2026-10-22 真机反馈「能横过来几秒，然后提示转不了横屏」，就是这个兜底把已经转过去的界面又转了回来。那条路 1.5 秒内没给出横着的大小，原因不明，所以不再靠它。
同一天的第二轮真机截图里，横屏全屏已经能转、播放器铺满页面。

为什么不是「放开方向，让系统播放器自己全屏」：第一版就是这么做的（进完整视频时放开方向，先 `["allButUpsideDown"]`，后来对着官方文档的示例改成 `["all"]`），
真机反馈是「横不了」。具体是点播放器自带的全屏没转、还是把手机横过来没转，反馈里没说，当时系统的方向锁定开没开也没问，所以**放开为什么没用，我没法确认**；
可能只是「允许」转、要手机真的横过来且方向锁定关着才转（官方文档里方向监听写了「系统方向锁开启时不会生效」）。能确定的是：强制只许横屏不依赖这些，手机竖着拿也转得过去。
顺带试过 `VideoPlayer` + overlay（想让系统全屏里也有字幕），有了自己的全屏就用不上，已经撤掉。播放器现在是 layer 模式的 `AVPlayerView` + 自绘控制条，见下一节。

**自己写播放器**（2026-10-23 做了，成品见下一节）：官方文档给了积木——`AVPlayerView` 的 `renderingMode="layer"` 只画视频层，配合 `VideoPictureInPictureController`
（Scripting 3.2.2 起）才能画中画，要显式传 `pictureInPictureController` 和 `pipStatus`，源视图和 AVPlayer 要一直挂着，不支持关掉页面或退出脚本后继续浮窗；
layer 模式没有原生控制条、自动画中画、全屏切换、Now Playing，这些都得自己做。代价是系统控制器自带的东西没了：隔空播放（AirPlay）按钮、
锁屏 / 控制中心里的播放信息、系统的全屏按钮、系统进度条的拖动手感；画中画改用 `VideoPictureInPictureController` 自己开（保活的做法没变：画中画开着时不销毁播放器）。

### 播放器控制条

2026-10-23 把系统控制器（`AVPlayerView` 的 controller 模式）换成了「只画画面」的 layer 模式 + 自绘控制条（`pages/PlayerControls.tsx`，纯逻辑在 `core/playerControls.ts`）。
原因：系统的控制条样子和按钮都改不了，没有倍速 / 画面比例 / 锁定 / 信息行，字幕入口也只能放在页面的小胶囊里。参考的是用户给的另一个播放器的截图。

**两种摆法，同一套按钮**：

- **全屏（横屏）**：顶栏从左到右是退出全屏、画面比例、画中画（支持时才有），中间片名（番号），右边倍速、分享、字幕；
  底栏是信息行（`2160p · 60FPS · 14.6mbps` 这种）、进度条（当前时间 · 滑条 · 总时长），再下面左边锁定、中间快退 10 秒 / 播放暂停 / 快进 10 秒。
- **小窗（竖屏、贴在页面顶上）**：右上角关闭；中间快退 / 播放暂停 / 快进；底部一排圆钮（倍速、画面比例、画中画、字幕、分享、全屏）加进度条。
  信息行只在全屏里画（小窗一排按钮已经占满了宽度）。来源标签（「MissAV 完整视频」）小窗里亮 4 秒就淡掉，放在关闭按钮的左边；全屏里不显示。

**行为**：

- 点一下画面亮 / 灭控制条；播放中停 3.5 秒自己淡掉（`HIDE_AFTER_MS`），暂停时一直亮着。淡掉靠透明度，视图一直挂着——菜单开着时控制条淡了，菜单不会被摘掉；
- **进度条**：拖动时只记手指的位置，松手才真的跳（HLS 上每动一下就跳会反复缓冲）；点一下不动不算拖，不会跳；时长不可用（直播、还没就绪）时只留两头的时间。
  当前时间由进度条这一行自己定时去读（250 毫秒），只重绘这一行，不连累画面和字幕；
- **倍速**：0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 / 3 倍，不是 1 倍时按钮上直接写数字。暂停时换倍速只记下、下次播放生效（直接改 `rate` 会让暂停的视频自己播起来）；
- **画面比例**：点一下依次切 适应 → 填充（裁掉多出的边）→ 拉伸，切换后弹一句提示（`videoGravity`）；
- **锁定**：锁上以后只剩一个解锁按钮，别的都不响应；点画面会让解锁按钮亮几秒；
- **画中画**：`VideoPictureInPictureController`，点按钮才开（要用户操作触发）；不支持或建不出来就没有这个按钮。画中画窗口里只有视频层，字幕跟不过去；
- **信息行**：另开一个 `AVAsset` 读视频轨的尺寸 / 帧率 / 码率（`kit/videoFacts.ts`，最多等 8 秒，读完马上释放），只给完整视频读；读不到的项省掉，一项都没有就不画这一行。
  **预期里对 HLS 多半读不到**（推测：AVFoundation 的 HLS 变体不以视频轨的形式暴露，`loadTracks("video")` 常返回空），而我们的完整视频（MissAV / Jable）大多是 HLS，所以这一行很可能一直是空的；
  真机上读不到的话，可以补一个自己解析 m3u8 里 `RESOLUTION` / `BANDWIDTH` / `FRAME-RATE` 的做法（没做）；
- **字幕**和**分享**：还是原来的菜单，只是变成控制条里的圆钮（字幕图标跟着状态变：查找中 / 已载入且显示 / 其它）。

**做不了的**（Scripting 没有对应的 API）：隔空播放（AirPlay）按钮、切换音轨、实时网速、编码（HEVC）/ 动态范围（HDR）标签、硬解码开关、HDR 字幕亮度、图形字幕（PGS）、
截图（`AVAsset.generateImage` 对 HLS 基本不行，我们的完整视频多是 HLS）、上一集 / 下一集 / 播放列表（影片没有）。

**没有在真机上看过**，是照类型定义和文档写的——见下面「已知局限」。

### 字幕（迅雷字幕库 + 字幕猫）

播放完整视频（MissAV / Jable 完整视频）时，播放器控制条里会多一个「字幕」按钮（圆钮，图标是带字幕的气泡），预览片段没有。
（早先用系统控制条，字幕按钮放在播放器右下角总被误点，挪到过页面上的小胶囊里；控制条换成自绘以后又搬了回来。）点开它选「搜索字幕」：

1. 拿番号去迅雷的字幕接口搜（`api-shoulei-ssl.xunlei.com/oracle/subtitle?name=…`，按文件名模糊搜的网友上传库）。
   一个番号换三种写法各搜一遍（`SSIS-123` / `SSIS00123` / `SSIS123`）：实测这个库对写法很敏感，`SSIS-123` 搜得到、`SSIS00123` 搜不到，
   `SSIS-001` 搜不到、`SSIS00001` 反而搜得到；
2. 结果拿文件名对一遍番号，不相干的滤掉（搜 `MIDE001` 会带出一堆别的节目的 `E001`）；同一份被传了很多遍的并成一条，
   文件名是「另一份的 gcid」的转存件也滤掉；
3. 排序：和视频时长差得少的在前（差五分钟以上的直接丢）> 被传得多的 > SRT 优先于 ASS；
4. 第一条自动下载、解码、画到画面底部。格式按内容认、不看扩展名（实测有 `.ass` 里装 SRT 的、丢了 `[Events]` 段头的 ASS），
   编码认 UTF-8（带不带 BOM 都行）/ GBK / UTF-16（实测有丢了 BOM、中间还坏了一截的，宽松解码，好的那些条照样出来）；
   打不开（链接失效、不是字幕）自动换同一份的备用链接，再不行换下一条。

**字幕猫（Subtitle Cat，朋友给的第二个来源）**：和迅雷同时搜、并发，一个连不上就用另一个的；候选里迅雷的在前，字幕猫的接在后面（`kit/subtitle.ts`，纯逻辑在 `core/subtitlecat.ts`）。
2026-10-22 实测的样子：

- 搜索是 `GET https://www.subtitlecat.com/index.php?search=<番号>`，回一页 HTML，一行一条（名字、`translated from <原始语言>`、大小 / 下载数 / 语言数，点过赞的有 👍）。
  **站上的搜索是按词模糊匹配的**：搜 IPX-123 会带出 IPX-239__English-123，搜 SDJS-385 回了 120 条、没有一条是它，所以要拿名字对回番号（和迅雷共用 `matchesCode`）。
  番号要带横杠（SSIS-001 有 4 条，SSIS00001 一条没有），所以只搜带横杠和紧凑两种写法（SSIS001 搜出过 SSIS001.FHD，是带横杠那 4 条之外的）；
- 详情页里每种语言一行：有现成文件的是「Download」链接（朋友给的 `…/subs/765/ABF-123.V4-zh-CN.srt` 这种，UTF-8 的 SRT，直接 GET 就行），没有的只有「Translate」按钮（浏览器里用 JS 现翻，脚本里不做）。
  **目录号每种语言不一样**（STARS-123 的原文在 307、zh-CN 在 308、zh-TW 在 315），猜不出来，所以点到那一条时才去读它的详情页（一百多 KB），从链接里找中文文件：
  简体 > 繁体，中文原版最后再退到原文（`…-orig.srt`）；
- 「translated from X」是这份字幕**原本**的语言：Chinese = 中文原版（人工字幕，和迅雷里的一个水平），其余是机翻（英文 / 日文 / 韩文 → 中文，意思能懂、不太通顺）。
  排序：中文原版 > 点过赞 > 下载多 > 语言多，最多留 6 条；机翻的条目没有中文文件就跳过、换下一条。菜单第一行里字幕猫的条目前面标着「字幕猫 · 中文原版」或「字幕猫 · 机翻自英文」，一眼看得出是哪种；
- 没有开关：只有你点「搜索字幕」/「换一条字幕」才会请求，请求里只有番号；一个来源连不上不影响另一个，两个都连不上才报错。

菜单里还有：显示 / 隐藏、换一条字幕（点一下换下一条，一圈后回到第一条）、字幕提前 / 延后 0.5 秒和 5 秒（剪辑版本对不上时用）、还原同步。
菜单第一行写着当前这条的来源（只有字幕猫的才写）、文件名、语言（粗略认的：中文 / 日文 / 英文）、条数、和视频的时长差（字幕猫的条目没有时长，不写）。

菜单里还有「字幕设置…」，打开一张玻璃质感的设置面板（`pages/SubtitlePanel.tsx`，和全 App 的胶囊、分段是同一个语气）：竖屏时浮在画面下方，
全屏时贴在画面右侧，调的时候画面和字幕都看得见（2026-10-22 的全屏截图里面板已经出来了，排版没问题；那时右缘还有一列按钮、面板让出了位置，现在没有了，只留一点边，面板盖在控制条上）。面板里有：
搜索 / 显示隐藏 / 换一条（字幕菜单里也有这些操作）；
**颜色**：白 / 黄 / 青 / 绿 / 粉五个预设，后面第六个带「#」的圆点点开填**色值**——`#FFE14A`、`FFE14A`、三位的 `#FC0` 都行，不合格式会提示、不改；选的不是预设色时这个圆点就是当前色；
**字号**：滑块，占「按叠层大小算出的基准字号」的 60%~200%（实际字号限制在 10~56 点），右边显示百分比；
**文字透明度**：滑块，20%~100%；**底色透明度**：滑块，0~100%，拖到 0 就是没有底条、只留一圈黑色阴影托着字；
**同步**（±0.5 秒、±5 秒、还原）、**排版**（「双层」开关、还原位置），右上角有「恢复默认」。拖滑块时字幕当场跟着变；外观和位置存在设置里（`subtitleStyle`），所有影片共用一份。
第一版存的是档位名（颜色 yellow、字号 large、底色开关），读存档时会换成现在的写法，已经调好的不丢。
外观的状态不放在详情页的 state 里，放在 `kit/subtitleLook.ts` 的全局状态：滑块拖一格就改一次，放在详情页里会让整页跟着重绘，现在只有字幕层和面板在重绘；
开关、选色、拖完位置马上存盘，滑块停下 0.4 秒再存，免得每一格写一次存储。

**拖着挪位置**：手指按在字幕上拖，想放哪儿放哪儿，松手就记住。位置存的是占叠层宽 / 高的比例、不是点数：竖屏小窗里拖好的位置，到了横屏全屏里还在差不多的地方，各种屏幕尺寸通用。
拖不出画面：往上最多到离顶边 4 行字高（三行的字幕也放得下），往下到离底边 6 点，左右各到离边 60 点。按字幕的范围比底条大一圈，不用精准按在字上；
没有字幕的时候这一层不接管触摸，点画面照样亮 / 灭控制条。第一次载入字幕时会提示一句可以拖。

这几处细节参考了朋友给的两份文档（`MISSAV-SUBTITLE-LANDSCAPE.md`、`MISSAV-SUBTITLE-DRAG-POSITION.md`）：位置存比例（他们的存档是绝对点数，横竖屏切换会跑偏，文档里自己也列了这条）、
拖动范围限制、命中区域放大、无效坐标丢弃、没有字幕时整层不接管触摸、拖动结束才写存档。没采用的：「位置 %」滑块（他们那个滑块算出的值没人用；拖动已经覆盖，两套位置机制只会互相打架）、
按影片分别记位置（先共用一份）、双指缩放字号（`MagnifyGesture` 和拖动叠在同一个视图上，真机上谁赢没法验证，字号用面板里的滑块调）。

**双层字幕**（朋友在油猴脚本里做过，说效果不错）：一行放不下的长句，拆成上下两层，每层一块自己的底条，不再挤成一大块盖住半个画面。规则在 `core/subtitleLayers.ts`：
原来就分行的（中日双语的两行）一行一层；单行超过一层放得下的宽度（按叠层宽度和字号估，汉字算 1、拉丁字母 0.55、空格 0.3），在中间附近断开，优先断在标点之后和空格处，
没有就在字间选离平分点最近的；标点、长音、小假名不落到行首，开括号、开引号不落到行尾；拉丁字母的词中间不断；一整串没处可断的（网址）原样留着；拆完总共超过 4 层就不拆。
面板里的「双层」可以关，关掉就是整句一块底条、让 Text 自己折行。

局限：

- 字幕是脚本自己叠在画面上的一层文字，不是视频里的字幕轨（Scripting 的 `AVPlayer` 没有开放外挂字幕轨）：小窗里和我们自己的全屏（点「全屏」）里都看得到；
  画中画窗口里只有视频层，这一层跟不过去（现在没有系统自带的全屏了）——要在别的播放器里带字幕，载入字幕后用分享菜单里的「SenPlayer 打开（带字幕）」，
  字幕交给 SenPlayer 渲染（见上面「外部播放器」）；
- 两个库都是网友上传的，覆盖不全。2026-10-22 对 18 个常见番号各搜了一遍（SSIS-001、SSIS-200、MIDE-500、STARS-123、JUL-123、CAWD-100、FSDSS-100、EBOD-500、PRED-300、MIAA-500、ABW-100、
  IPX-500、HND-500、ADN-300、SDJS-385、ABF-123、CJOD-300、WANZ-500）：迅雷有 13 个、字幕猫有 10 个（其中 6 个有中文原版）、只有字幕猫有的 1 个（ABF-123，而且只是机翻）、
  两边都没有的 4 个（IPX-500、SDJS-385、CJOD-300、WANZ-500）。更早用另一批 35 个番号只测过迅雷：17 个有对得上的。两批名单不一样，数字不能直接比；
- 字幕猫里机翻的占多数（原文是英文 / 日文 / 韩文，翻成中文），读起来能懂但不通顺；有中文原版的优先，菜单第一行写着是哪种；
- 同一个番号常有几个版本的字幕，视频时长对不上就会整体错位，用「提前 / 延后」调；语言不保证是中文，看菜单第一行，不对就「换一条」；
- 请求里只有番号，字幕文件从迅雷自己的 CDN / 字幕猫的站上下，见下面「数据去向」。

## 数据去向

脚本会请求下面这些地址，没有统计、没有任何别的上报：

| 地址 | 用途 | 什么时候发 |
|---|---|---|
| `www.javbus.com` / `www.javbus.org`（含图片 CDN） | 列表、搜索、详情、磁链、图片 | 浏览时 |

## 站点年龄验证

`www.javbus.com` 现在会把请求 302 到 `/doc/driver-verify`（勾选「我已經成年」再提交的页面），原脚本没处理这个——
大概与地区有关，在不被要求验证的网络下它不会出现。这里的处理：

1. `kit/http.ts` 的 `getPage` 认出验证页（地址或 `id="ageVerify"`），**先弹窗问你一次**要不要代你向站点提交这次确认
   （你同意后记住，之后不再问；拒绝就不提交、不绕过）；
2. 同意后 POST `Submit=確認` 到验证页，吸收响应里的 cookie，重试原请求；
3. 没生效就提示你**打开真网页亲手勾选**（`kit/session.ts` 的 `manualAgeVerify`），关掉网页后把 web 视图里的 cookie 读回来。
   这一条不需要猜站点用哪个 cookie，是最后的兜底。设置页里也有常驻入口。

cookie 罐落盘在 Storage（`javbus.cookies`），按 `.com` / `.org` 分开，只带给 javbus 自家域名。

## 几个反直觉的地方

**磁链表是页面脚本异步补的。** 详情页内联脚本里有 `var gid / uc / img / lang`，`/js/gallery.js` 末尾拿它们拼
`ajax/uncledatoolsbyajax.php?gid=…&lang=…&img=…&uc=…&floor=…`，响应是一串 `<tr>` 追加进 `#magnet-table`。
原版靠隐藏 web 视图拦这个子请求；Scripting 的 `WebViewController` 拦不到子请求，所以 `kit/magnets.ts` 直接 fetch 同一个地址，
只有「请求失败」或「响应非空却一行磁链都解析不出」（多半被挑战页挡了）时才退到 `WebScraper` 真加载页面等 `#magnet-table a[href^="magnet:"]`。
响应本身为空是「确实没有磁链」，不走兜底——等 selector 会白等到超时。

**图片要带 Referer，`<Image imageUrl>` 带不了。** 所以 `kit/images.ts` 自己 fetch → `UIImage.fromData`，内存 LRU（240 张）+
并发 6 路封顶 + 同一张图的并发请求合并；列表缩略图解码后缩到最长边 360px 省内存。cookie 只给 javbus 自家域名带，
Referer 对所有图片都带（原版如此）。

**MissAV 完整视频要真浏览器内核。** 隐藏 `WebViewController` 加载 `missav.ws/<番号>`（9.2 起从 .ai 换成 .ws），每 300ms 查一次
`video.player` 的 `src`，最长 80 秒（9.1 是 12 秒、读 `currentSrc`；原版说 .ws 现在返回的是 HLS）。等得这么久，
所以全局同一时刻只开一个 web 视图，同一番号的请求合并、找到的地址按番号缓存，预取任务在请求方离开详情页后会被跳过、
已经在等的也会立刻收摊——否则连着翻几部会叠出一堆隐藏的 WKWebView，后面的片还要被前面占着的 80 秒堵住。

**详情页所有「推」出去的子页面走同一个 `dest` 状态 + `navigationDestination`。** 菜单项里放不了 `NavigationLink`，
统一一个出口也让「返回」行为只有一处要验证。

**推进来的页面不能用 `Navigation.useDismiss()` 返回。** 它拿到的是「把外层界面呈现出来的那个东西」，
在推入页里调用会关掉整个脚本。根页面的「关闭」按钮 / 设置页 / 文案页（都是 `Navigation.present` 弹出来的）才用它。

**依赖「用户真的看到了这个 Tab」的副作用要放 `onAppear`，不能放挂载。** 推荐页的「新」角标清除和首次提示
就是这样——Tab 内容如果启动时就全部挂载，放在挂载里会在没人看见时把角标清掉、把提示弹出来。

**Menu / Button 的 label 里写弹性宽度（`frame({ maxWidth: "infinity" })`）在真机上不会撑开。**
详情页底栏第一版就栽在这：三个按钮缩成文字那么宽，整条底栏成了一小块悬在屏幕中间、压住上面的内容。
所以现在需要等宽 / 定宽的地方（详情页的播放胶囊和收藏胶囊）都按 `Device.screen.width` 算死（`columnWidth`，iPad 封顶），
不指望弹性宽度。详情页的底栏本身已经没有了；样品图页底部那条的进度条也是固定宽度（200）。

**整个脚本是深色设计，不管系统明暗。** 锁定的位置都在 presentation 的根上：App 的 `TabView`，加上单独 `Navigation.present` 出来的
设置、文案页（写在各自的 `NavigationStack` 上）和 18+ 提示——不去赌 modal 继承不继承根视图的外观，各自再锁一次。
自己画的字和图标全用明确的白色系（`INK`），不用 `label` / `secondaryLabel`：它们跟系统明暗走，锁定一旦没生效就会变成深灰字落在深色底上。
`preferredColorScheme` 不写在推入页里面——One-ipa 里实测它在 TabView + NavigationStack 的推入页里不可靠；根上的写法有 网易云音乐 的真机先例。
详情页另外把导航栏设成透明（`toolbarBackgroundVisibility`）、`toolbarColorScheme` 锁深色，`environments.colorScheme = dark` 只套在内容上，
是只锁一页时留下的做法，整个脚本锁深之后是双保险。
背景的糊法照 One-ipa：只解 48 像素的小图再放大 1.4 倍，双线性放大本身就是模糊；整屏的大半径 `blur` 每次转场都要 GPU 现算，会掉帧，
所以没有封面可糊的页面只用渐变。

**自绘的分段（`Segmented`）要整段可点、且只在选中项变了才回调。** plain 按钮没有背景的那几段点击区只有字形那么大，
所以 Text 上要写 `contentShape`；系统分段控件重复点已选中项不回调，首页「重复点已选中的分区」不该把搜索结果清掉。
每段宽度按列宽算死（Button 的 label 里弹性宽度不撑开），首页把「分区」和「范围」并排放时，两条的宽度加间距正好等于内容列宽。

**详情页和样品图页让出 Tab 栏（`toolbarVisibility`）。** iOS 26 的 Tab 栏是浮在内容之上的
玻璃胶囊，不让的话会压住页面底部。再往里推的页面（类目、演员）Tab 栏会照常回来。

**带 `Spacer` 的整行按钮要加 `contentShape="rect"`。** SwiftUI 里 Spacer 那一段默认不响应点击，
不加的话设置页的「标题 …… 当前值」行只有两端的文字点得到。

**TabView 的选中项用 `useObservable`，不用 `useState`**（同 网易云音乐 README：受控 `tabIndex` 配 `useState` 时
根视图一重渲染就会把 TabView 重新定位）。根视图会因轻提示、推荐角标重渲染，所以尤其要这样。

**列表行里的一排按钮必须 `buttonStyle="borderless"`**，否则整行只有最后一个会响应。详情页的底栏、播放器的快进快退、
类别胶囊都因此带这个样式。

**轻提示是一摞宿主**（`kit/toast.ts`）。设置页、文案页是 `Navigation.present` 整页弹出的，会盖住 TabView 上的提示，
所以它们各自登记一个宿主，卸载后上一个自动接回来。

**`usePaged` 用 token 作废旧请求。** 切分区 / 换关键词 / 切全部收录会让在途的旧请求变成过期响应，慢的旧响应回来时不能覆盖新列表。
换站搜索命中后，命中站点的第一页作为 `seed` 直接铺列表，不再请求一遍。
